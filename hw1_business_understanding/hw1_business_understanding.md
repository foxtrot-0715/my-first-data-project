# Домашнее задание №1: Бизнес-анализ (Business Understanding)

## 1. Бизнес-анализ (Business Understanding)

### Организационная структура

- **Заказчик:** Руководитель департамента информационного мониторинга / Аналитический центр при органах государственного управления.
- **Основной пользователь:** Аналитик социально-политических процессов, специалист по связям с общественностью (PR), маркетолог.
- **Команда проекта:** Data Scientist / ML Engineer (разработчик модели и инфраструктуры), Full-stack разработчик (Python/FastAPI + Angular).
- **Экспертная поддержка:** Консультации экспертов курса MLOps на каждом этапе CRISP-DM.
- **Рабочие чаты / коммуникация:** Контур Толк, Telegram-чат с экспертами курса, репозиторий GitHub.

### Бизнес-цель проекта

Создание автоматизированной системы мониторинга и визуализации эмоционального состояния общества в режиме реального времени. Основная задача — оперативное выявление социальных рисков и кризисных ситуаций через анализ тональности (Sentiment Analysis) сообщений в социальных сетях с привязкой к географическим регионам РФ.

**Ключевые бизнес-цели:**
- Сокращение времени получения аналитической сводки по инфоповоду с нескольких часов (ручной мониторинг) до **менее 1 минуты**.
- Обеспечение возможности **региональной сегментации** общественных настроений (привязка к субъектам РФ через ISO-коды).
- Переход от **реактивного** управления информационной повесткой к **проактивному** (раннее выявление очагов социальной напряжённости).

### Существующие решения и их недостатки

| Существующее решение | Недостатки |
|----------------------|------------|
| Ручной мониторинг комментариев аналитиками (анкетирование, отслеживание ключевых слов) | Низкая скорость обработки, субъективность, невозможность охватить весь объём неструктурированных данных (Big Data) |
| Готовые платформы (Brandwatch, YouScan, «Медиалогия») | Высокая стоимость, недостаточная адаптация под российскую региональную специфику, отсутствие оперативной геовизуализации в реальном времени |
| Отсутствие единого инструмента | Данные разрознены, нет связи между NLP-анализом и интерактивной картографией |

## 1.2 Решаемые задачи с точки зрения аналитики (Data Mining goals)

### Постановка ML-задачи

**Тип задачи:** Многоклассовая классификация коротких текстовых сообщений на три категории тональности.

- **Входные данные (X):** Тексты постов, комментариев и сообщений из целевых платформ (VK, Telegram, «Одноклассники», Pikabu, Rutube, Яндекс.Дзен).
- **Целевая переменная (Y):**
  - **Позитив** (одобрение, поддержка).
  - **Негатив** (осуждение, критика, протест).
  - **Нейтрально** (информационные сообщения без эмоциональной окраски).
- **Дополнительные данные:** Географическая привязка (ISO-код региона), метрики вовлечённости (количество реакций, лайков, репостов).

### Метрики оценки модели

| Метрика | Описание | Минимальный порог | Целевое значение |
|---------|----------|-------------------|------------------|
| **F1-мера (weighted)** | Средневзвешенное гармоническое между Precision и Recall по трём классам. Выбрана как основная метрика для баланса в условиях естественного дисбаланса классов (например, резкий всплеск негатива в кризисные периоды) | ≥ 0.70 | ≥ 0.80 |
| **Accuracy** | Общая доля правильных ответов (для общей оценки качества) | ≥ 0.75 | ≥ 0.85 |
| **Confusion Matrix** | Матрица ошибок классификации | — | Качественный анализ ошибок между классами «негатив» и «нейтрально» |

### Критерии успешности модели

- **Минимальный порог:** F1-мера (weighted) ≥ 0.70. Если модель ниже — требуется пересмотр данных или архитектуры.
- **Оптимальный целевой показатель:** F1-мера (weighted) ≥ 0.80. При достижении этого значения модель считается готовой к внедрению.
- Дополнительно: визуальный анализ Confusion Matrix для выявления систематических ошибок (например, путаница между «негативом» и «нейтральным» классом).

## 1.3 План проекта (Project Plan)

| Фаза | Содержание | Ожидаемый результат |
|------|------------|---------------------|
| **1. Бизнес-анализ** | Формализация целей, критериев успеха, рисков. Выбор стека и источников данных. | Данный документ (Business Understanding). |
| **2. Анализ данных (Data Understanding)** | Сбор первичного датасета из VK/Telegram. Анализ распределения классов, региональных меток, качества текстов. | Отчёт о распределении данных, выявленные проблемы (дисбаланс, шум). |
| **3. Подготовка данных (Data Preparation)** | Очистка текстов от шума (ссылки, эмодзи), токенизация, векторизация. Аугментация через back-translation. | Готовый к обучению датасет. |
| **4. Моделирование (Modeling)** | Baseline: классические алгоритмы (CatBoost на TF-IDF). Основная модель: дообучение RuBERT-tiny2. Подбор гиперпараметров. Error analysis. | Обученная модель с задокументированными метриками. |
| **5. Оценка (Evaluation)** | Тестирование лучшей модели на отложенной выборке. Валидация экспертами. Сравнение с предобученной версией без дообучения. | Отчёт о качестве модели. Решение о готовности к деплою. |
| **6. Внедрение (Deployment)** | Обертывание модели в API (FastAPI). Создание фронтенда на Angular для визуализации карты реакций. Контейнеризация (Docker). CI/CD (GitHub Actions). | Production-сервис, доступный пользователям. |
| **7. Мониторинг** | Настройка отслеживания метрик модели после деплоя (Prometheus + Grafana). Алерты при падении качества. Конвейер дообучения при обнаружении Data Drift. | Стабильно работающий сервис с оперативным обнаружением проблем. |
