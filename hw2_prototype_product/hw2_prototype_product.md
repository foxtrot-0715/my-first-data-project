# Домашнее задание №2: Создаем прототип продукта

## 1. Ключевая гипотеза

Если сегменту **PR-аналитиков и специалистов по мониторингу социальных медиа (B)** в сценарии **оперативного анализа общественного резонанса на новостной инфоповод (C)** предоставить продукт **«Карта социальных реакций» — веб-приложение, автоматически собирающее публичные комментарии к новости из легальных источников (Reddit API, Rutube API, RSS-ленты) и отображающее их тональность на интерактивной карте регионов РФ (A)**, то мы получим **среднее время получения аналитической сводки не более 5 минут (D)** в течение **месяца тестирования (T)**, потому что **автоматический сбор и NLP-анализ заменят 80% ручной работы аналитика по поиску и первичной оценке комментариев (причина)**.

## 2. Ключевые метрики

### Продуктовые метрики

| Метрика | Значение | Способ замера | Baseline | Частота |
|---------|----------|---------------|----------|---------|
| **Время получения аналитической сводки (Time-to-Insight)** | ≤ 5 минут | Автоматический лог: разница между временем отправки запроса пользователем и временем отображения результата на фронтенде | 30–60 минут (ручной мониторинг) | Каждый запрос |
| **Географическое покрытие** | ≥ 80% субъектов РФ | Сравнение количества регионов, по которым система вернула данные, с общим числом субъектов РФ (85) | 10–15% (ручной мониторинг одного-двух регионов) | Еженедельно |
| **Количество источников, успешно опрошенных за один запрос** | ≥ 2 из 3 (Reddit API, Rutube API, RSS) | Лог успешных/неуспешных обращений к API. Метрика = доля запросов, где успешно отработали ≥ 2 источника | 0 (системы нет) | Еженедельно |
| **Доля успешных запросов (Uptime продукта)** | ≥ 95% | Отношение количества запросов, завершившихся успешно (HTTP 200 + результат), к общему числу запросов | 0 (системы нет) | Ежедневно |

### Технические метрики

| Метрика | Значение | Способ замера | Baseline | Частота |
|---------|----------|---------------|----------|---------|
| **F1-score (weighted)** | ≥ 0.80 | Стандартный расчёт на отложенной тестовой выборке (из открытых датасетов RuSentiment, CEDR) | 0.70 (минимальный порог из ДЗ №1) | Каждая итерация модели |
| **Скорость инференса модели** | ≤ 100 мс на один текст (CPU) | Автоматический замер времени вызова `model.predict()` в коде | ~200 мс (baseline RuBERT-tiny2 без оптимизаций) | Каждый билд |
| **Время полного цикла обработки запроса (end-to-end latency)** | ≤ 30 секунд | Лог на бэкенде: от получения запроса до отправки JSON-ответа | Неприменимо (нет системы) | Каждый запрос |
| **Количество ошибок классификации на «сложных» примерах** | Снижение на 20% относительно baseline | Ручная экспертная оценка на выборке из 50 примеров с сарказмом и иронией | Ошибка baseline-модели на этой же выборке | Каждая итерация модели |

## 3. Scope прототипа (что входит, что намеренно не делаем)

### ✅ Что входит в прототип (MVP)

1. **RSS-коннектор:** Подписка на 10–15 RSS-лент федеральных и региональных СМИ. Извлечение заголовка, текста новости, даты, источника. Определение региона через NER (библиотека Natasha).
2. **Reddit API-коннектор:** Поиск обсуждений по ключевым словам из новости в русскоязычных сабреддитах. Сбор комментариев.
3. **Rutube API-коннектор:** Поиск видео по теме новости, сбор комментариев под ними.
4. **NLP-модель (Sentiment Analysis):** Дообученная RuBERT-tiny2 для классификации тональности на 3 класса (позитив/негатив/нейтрально). Обучена на открытых датасетах (RuSentiment, CEDR).
5. **Геокодирование:** NER-извлечение топонимов из новостей и комментариев → OpenStreetMap → координаты для карты.
6. **Веб-интерфейс (Angular):**
   - Строка поиска (ключевое слово или выбор из предложенных тем).
   - Интерактивная карта РФ (Яндекс.Карты API) с цветовой индикацией тональности по регионам.
   - Простая статистическая панель: круговая диаграмма распределения тональности, топ-5 регионов по активности.
7. **Бэкенд (FastAPI):** Асинхронная обработка запросов, оркестрация API-коннекторов и NLP-модели.

### ❌ Что намеренно НЕ делаем и почему

| Исключено | Причина |
|-----------|---------|
| Парсинг Telegram, VK, «Одноклассников» | Нарушение ToS платформ. Юридические риски на этапе прототипа неприемлемы |
| Хранение персональных данных пользователей | Выводит прототип из-под 152-ФЗ. Работаем только с обезличенными публичными данными |
| Бессерверное развёртывание (лямбды) | Избыточно для MVP. Прототип работает на одном сервере. Масштабирование — фаза 6 |
| Мониторинг Data Drift и алерты (Prometheus + Grafana) | Критично для продакшена, но не для проверки гипотезы. Оставляем на фазу 7 |
| Поддержка нескольких пользователей одновременно | Прототип проверяет гипотезу на одном сценарии. Многопользовательность — задача продакшена |

## 4. Готовые блоки vs своя разработка

| Компонент | Готовое / Сами | Обоснование |
|-----------|----------------|-------------|
| **RuBERT-tiny2 (предобученная)** | Готовое (Hugging Face) | Экономит недели на обучении. Хорошо работает на CPU |
| **Датасеты (RuSentiment, CEDR)** | Готовое (открытые) | Размечены, верифицированы. Не требуют затрат на сбор |
| **FastAPI** | Готовое (фреймворк) | Стандарт для Python-бэкендов. Асинхронность из коробки |
| **Angular** | Готовое (фреймворк) | SPA, строгая типизация, интеграция с картами |
| **Яндекс.Карты API** | Готовое (внешний сервис) | Точная детализация регионов РФ, готовая интерактивность |
| **Natasha (NER)** | Готовое (библиотека) | Специализирована под русский язык. Извлекает топонимы |
| **OpenStreetMap (геокодинг)** | Готовое (внешний сервис) | Бесплатный, открытый, точный для РФ |
| **Дообучение модели (fine-tuning)** | Делаем сами | Критично: адаптируем модель под специфику соцсетей (сленг, сарказм) |
| **API-коннекторы (RSS, Reddit API, Rutube API)** | Делаем сами | Критично: уникальная логика сбора под нашу архитектуру «на лету» |
| **Модуль геолокации (NER + геокодинг)** | Делаем сами | Критично: связка Natasha + OpenStreetMap — наше ноу-хау для продукта |
| **Гибридный алгоритм оценки тональности** | Делаем сами | Критично: комбинирует NLP-анализ текста и учёт пользовательских реакций |

## 5. Главный риск и формат прототипа

### Главный риск, который проверяем прототипом

**Гипотеза о работоспособности:** «Можно ли с помощью только легальных источников (Reddit API, Rutube API, RSS) собрать достаточно данных, чтобы сформировать репрезентативную картину социальных реакций на новостной инфоповод с географической привязкой?»

Мы НЕ проверяем качество NLP-модели (это уже доказано открытыми датасетами). Мы проверяем **полноту и репрезентативность данных**, собранных легальным путём.

### Конечный формат прототипа

Работающее веб-приложение, в котором пользователь вводит поисковый запрос (тему), и в течение ≤ 5 минут получает:
1. Интерактивную карту РФ, где регионы окрашены в цвета по доминирующей тональности (зелёный — позитив, красный — негатив, серый — нейтрально).
2. Круговую диаграмму распределения тональности по всей стране.
3. Топ-5 регионов с наибольшей активностью обсуждения.
4. Список источников, с которых были собраны данные.

## 6. Критерии остановки теста прототипа

### Тест считается успешным (переходим к продакшену)

| Критерий | Условие |
|----------|---------|
| **Полнота данных** | ≥ 70% тестовых запросов возвращают данные минимум из 2 источников (Reddit + Rutube или Reddit + RSS) |
| **Геопокрытие** | Хотя бы по 50% запросов система находит данные для ≥ 3 регионов РФ |
| **Скорость** | Среднее время ответа ≤ 5 минут (Time-to-Insight) |
| **Качество модели** | F1-score (weighted) ≥ 0.80 на тестовой выборке |

### Тест считается неуспешным (пересматриваем подход)

| Критерий | Условие |
|----------|---------|
| **Недостаток данных** | > 50% запросов возвращают менее 10 комментариев суммарно со всех источников |
| **Геопокрытие** | < 3 регионов РФ получают данные в > 50% запросов |
| **Скорость** | Среднее время ответа > 10 минут в течение недели тестов |
| **Качество модели** | F1-score (weighted) < 0.70 (ниже минимального порога) |

**Длительность теста:** 2 недели. **Тестовых инфоповодов:** 10 реальных новостей, отобранных вручную.
